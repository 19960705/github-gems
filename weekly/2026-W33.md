## 孵化候选

### 🥇 候选一：CSV 极简 EDA Agent（中文数据解读工具）

**来源项目**：[Chenmo0414/tukey](https://github.com/Chenmo0414/tukey)（本周报告：daily/2026-08-21.md）

**核心创新点**：tukey 是开源版 Julius AI——挂一个 CSV 或 Postgres 库，agent 自动剖析数据结构、用 SQL 回答问题、在对话里直接画 Vega-Lite 图表，把"数据分析师"直接装进 coding agent。妙在它把数据分析的完整闭环（连接→理解→查询→可视化）收敛成一个 agent 插件，数据洞察不再需要离开对话。

**你的简化版怎么做**：
- 砍掉：Postgres 连接、多数据源、agent 插件形态（不依赖具体 coding agent），全部砍掉。
- 保留：CSV 上传 → 自动 profiling → 生成 3-5 张关键图 + 一段中文解读的核心闭环。
- 差异化：面向"要写周报/汇报的数据同学"，输出是**可直接粘贴的中文结论**而不是图表工具本身；技术栈用 Python + DuckDB + 免费图表库（matplotlib/plotly），单文件 Web 界面，上传 CSV 即可用，不搭 Postgres。

**Vibe Coding 开工 prompt**：
```
做一个单文件 Python Web 应用（Streamlit 或 FastAPI+HTML），叫 csv-eda。
功能：用户上传一个 CSV 文件后，自动完成数据剖析并输出一份"可直接贴进周报的中文分析"：
1. 用 DuckDB 读 CSV，自动推断每列类型（数值/分类/日期），统计缺失值、唯一值、异常值；
2. 对数值列自动生成描述性统计（均值/中位数/分位数/标准差）；
3. 自动选 3-5 张最有信息量的图（相关性热力图、数值分布、时间趋势、分类占比），用 matplotlib 或 plotly 生成，中文标签；
4. 用 LLM（OpenAI 兼容接口，可配置 base_url 和 api_key，默认本地可跑）基于统计数据生成一段 3-5 句的中文解读：数据规模、核心发现、异常点、一句话结论。
验收标准：上传一个 1 万行以内的 CSV，60 秒内完成全部剖析与图表生成；解读段落无英文残留、可直接复制使用；LLM 不可用时降级为只出统计与图表并提示。
技术要点：Python 3.11+，依赖仅 duckdb、pandas、plotly/matplotlib、requests（LLM 调用用裸 HTTP 即可）、streamlit 或 flask。代码控制在 500 行内，图表用中文 rcParams 设置。
```

### 🥇 候选二：通用 Agent 生成 UI 运行时（JSON schema 描述界面，流式渲染）

**来源项目**：[CNSeniorious000/dsh-generative-ui](https://github.com/CNSeniorious000/dsh-generative-ui)（本周报告：daily/2026-08-22.md）

**核心创新点**：让 agent 直接"写界面"而不是"说方案"——模型还在生成时 React 组件就流式渲染出来，支持 chat 内联和 canvas 面板两种形态，相当于把 Claude Artifacts 的体验下沉到开源 harness，而且做到边输出边渲染。本周另一个相关信号是 star-burxt（"写文档就是写前端"，拼错变量在页面存在之前就报错）——"内容即界面"正在成为独立方向。

**你的简化版怎么做**：
- 砍掉：DeepSeek Harness 绑定、TSX 解析、React 专属渲染器，全砍。
- 保留：核心体验——LLM 输出结构化界面描述 → 前端流式渲染为可交互 UI 的运行时。
- 差异化：把界面描述从 TSX 换成 **JSON schema**（type/children/props），只接 OpenAI 兼容接口，前端渲染器用原生 JS 或任何框架，让**任何** agent（Claude/Codex/本地 Ollama）都能吐可交互 UI，做成一个 200 行的 npm 包而非 harness 插件。

**Vibe Coding 开工 prompt**：
```
做一个"LLM 流式渲染 UI"的最小运行时库（vanilla TypeScript，无框架依赖），叫 schema-ui。
核心链路：
1. 定义 UI 描述协议：一个 JSON schema 描述界面树，节点类型限定为 container/text/input/select/button/chart/table 六类，每类有 props（如 text 的 content、button 的 label+onClick 事件名），树深度不限但节点数上限 50；
2. 接入任意 OpenAI 兼容接口（可配置 base_url/model/api_key，支持 stream=true 流式返回），system prompt 要求模型"只输出一个 JSON 界面描述，不要解释"；
3. 实现流式渲染器：LLM 每吐出一段 JSON 就增量解析（用流式 JSON 解析器如 jsonparse），把已完成的节点渲染到 DOM，未完成的显示骨架占位，实现"边生成边出界面"的效果；
4. 事件系统：button 的 onClick 通过事件注册表回调，支持最简交互（点击按钮 → 调 LLM 继续生成下一个界面）。
验收标准：在浏览器 demo 页面里，用本地 Ollama 或任意 OpenAI 兼容端点，让模型"生成一个计算器界面"，能看到界面组件边生成边出现、3 秒内完整可交互；整个库源码不超过 400 行；无 React 等框架依赖；README 给出 5 行接入示例。
```

### 🥇 候选三：单动作姿势教练（浏览器即开即用的健身动作校验）

**来源项目**：[e4tsai-byte/rehab](https://github.com/e4tsai-byte/rehab)（本周报告：daily/2026-08-22.md）

**核心创新点**：rehab 是个人术后康复催生的 CV 康复教练——摄像头识别肩部手术康复动作，实时校验角度和姿势、给出可量化的反馈，数据本地保存。它切的是"家庭物理治疗没人监督动作变形"的真实痛点，把原本需要专业设备的动作评估压缩到摄像头+算法。

**你的简化版怎么做**：
- 砍掉：多动作支持、康复医疗场景、数据留存系统，全砍。
- 保留：核心闭环——摄像头识别人体姿态 → 实时校验单一动作的角度/次数 → 给量化反馈（如"深蹲角度不够 90°"）。
- 差异化：只做**深蹲/平板支撑**这类健身新手动作（不用碰医疗），用 MediaPipe Pose + 浏览器原生 API（getUserMedia + 纯前端推理），**零安装零外设**，手机/电脑浏览器打开就能用，目标用户是健身新手和居家训练人群，比康复场景门槛低得多、受众大得多。

**Vibe Coding 开工 prompt**：
```
做一个纯前端的"姿势教练"单页应用（HTML + JS，用 MediaPipe Pose 做姿态估计，CDN 引入，无需后端），叫 pose-coach。
功能（第一版只支持"深蹲"一个动作）：
1. 打开页面即请求摄像头权限（getUserMedia），实时显示视频画面 + 骨骼关键点叠加（MediaPipe Pose 默认 33 关键点）；
2. 深蹲检测算法：用髋、膝、踝三个关键点计算膝关节角度，用肩、髋、膝计算躯干前倾角；判定规则——下蹲期（膝盖角度从 >160° 降到 <90°）和站起期（回到 >160°），完成一次深蹲计入次数；若膝盖角度从未低于 100° 则判"蹲得不够深"，躯干前倾超过 45° 判"弯腰"；
3. 实时反馈 UI：顶部大号数字显示当前膝盖角度，旁边显示状态灯（绿=标准 / 黄=蹲浅 / 红=弯腰），底部累计次数；每次状态切换用语音（SpeechSynthesis）提示"太浅了""注意腰背"；
4. 全程本地计算，无任何网络请求（除 CDN 加载 MediaPipe 库）。
验收标准：在真实摄像头前完成 5 次标准深蹲能准确计数；故意只蹲一半能被识别为"蹲浅"并语音提示；页面在手机浏览器（Chrome）和桌面 Chrome 都能跑；单 HTML 文件，代码可读。
技术要点：MediaPipe Tasks Vision 的 PoseLandmarker，webgpu 或 wasm 后端；帧率控制在 15fps 即可；所有阈值做成页面顶部可调参数。
```
